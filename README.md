# Noventix — پلتفرم آموزش پروژه‌محور هوش مصنوعی

سایت فارسی و راست‌به‌چپ برای یادگیری پایتون، علم داده، یادگیری ماشین و یادگیری عمیق؛ همراه با پنل دانش‌آموز، پنل مالک و پنل ادمین.

این پروژه دو خروجی مستقل از یک کاتالوگ مشترک دارد:

| خروجی | محل | اجرا |
| --- | --- | --- |
| سایت استاتیک (نمایشی) | `site/` | GitHub Pages — بدون نیاز به سرور |
| اپلیکیشن PHP (واقعی) | `public/` + `src/` | هر هاست PHP یا سرور اختصاصی |

## نمایش سایت روی GitHub Pages

پوشه `site/` با اجرای `python3 tools/gen.py` از همان کاتالوگ `src/data.php` ساخته می‌شود و شامل همه صفحات (عمومی، مقاله‌ها، پروژه‌ها، انجمن و هر دو پنل) است. فایل `.nojekyll` هم در خروجی قرار می‌گیرد تا مسیرهای فارسی سالم بمانند.

```bash
bash tools/build.sh     # کاتالوگ را بررسی، سایت را می‌سازد و لینک‌ها را تست می‌کند
```

در این نسخه، PHP اجرا نمی‌شود؛ بنابراین فرم‌ها و پنل با ذخیره‌سازی مرورگر (`localStorage`) کار می‌کنند. کد تأیید در رابط کاربری نمایش داده نمی‌شود و ثبت‌نام واقعی با کد پیامکی فقط در اپلیکیشن PHP انجام می‌شود. هیچ داده‌ای به سرور ارسال نمی‌شود.

در تنظیمات کنونی GitHub Pages، شاخه `main` از ریشهٔ مخزن منتشر می‌شود. فایل `index.html` در ریشه، صفحهٔ اصلی را نمایش می‌دهد و لینک‌ها و دارایی‌ها از `site/` بارگیری می‌شوند؛ پیش از انتشار، `bash tools/build.sh` را اجرا کنید تا هر دو خروجی به‌روز شوند. برای تغییر محل انتشار، مقدار `SITE_PATH` در `tools/gen.py` و `BASE` در `tools/verify.py` را با مسیر عمومی جدید هماهنگ کنید.

## میزکار مشترک پایتون

نسخه PHP اکنون مسیرهای `dashboard/workspace` و `dashboard/workspace-templates` را برای فایل‌های خصوصی، پروژه‌های کاربر و الگوهای مدیر دارد. موتور جداگانه در `services/python-runner/` قرار دارد و بدون HTTPS، پیکربندی و استقرار gVisor فعال نیست. نسخه GitHub Pages همچنان نمایشی و مستقل است؛ ذخیره‌سازی سروری یا اجرای ایزوله با انتشار فایل HTML فعال نمی‌شود.

بخش Datasets همان میزکار، جست‌وجو و دریافت دیتاست‌های عمومی کوچک Hugging Face را بدون توکن از سمت PHP انجام می‌دهد. فایل‌های CSV/JSON/TXT با checksum و سهمیه در storage خصوصی دیسک نگهداری می‌شوند؛ محتوای دیتاست وارد DB نمی‌شود. هر فایل حداکثر ۱ MiB و هر دریافت حداکثر ۱۰ فایل و ۲ MiB است؛ private/gated، آرشیو، Parquet و CDN خارجی پشتیبانی نمی‌شوند. دریافت واقعی Iris با PHP/HTTP آزموده شده؛ اجرای آن در gVisor هنوز NOT TESTED است.

معماری، محدودیت‌ها، مهاجرت افزایشی، آزمون‌ها و راه‌اندازی: [راهنمای میزکار پایتون](docs/python-workspace.md).

## پیش‌نیاز (اپلیکیشن PHP)

- PHP نسخه ۸.۲ یا بالاتر با افزونه‌های `pdo_sqlite` (پیش‌فرض)، `mbstring` و `curl`؛ برای واردکردن ZIP افزونه `zip`
- وب‌سرور با ریشه داکیومنت روی پوشه `public/`
- برای MySQL، افزونه `pdo_mysql`

## راه‌اندازی

```bash
# اجرای محلی
php -S localhost:8000 -t public

# تنظیم پایگاه‌داده MySQL (اختیاری؛ پیش‌فرض SQLite است)
export DB_DSN="mysql:host=localhost;dbname=noventix;charset=utf8mb4"
export DB_USER=noventix
export DB_PASSWORD=...

# ارسال کد تأیید با متد Verify در SMS.ir (بدون این مقادیر، ثبت‌نام با کد فعال نمی‌شود)
export SMSIR_API_KEY="..."            # کلید پنل SMS.ir ← برنامه‌نویسان؛ فقط روی سرور
export SMSIR_TEMPLATE_ID="..."        # شناسهٔ قالب تأییدشده در «ارسال سریع»
export SMSIR_CODE_PARAMETER="Code"    # نام متغیر قالب بدون #
export OTP_TTL_SECONDS=300            # اعتبار کد: ۶۰ تا ۹۰۰ ثانیه
export OTP_MAX_ATTEMPTS=5             # تلاش ناموفق مجاز برای هر کد: ۱ تا ۵
export OTP_RESEND_COOLDOWN_SECONDS=90 # فاصلهٔ حداقل بین دو درخواست کد برای یک شماره
export OTP_RESEND_LIMIT=5             # حداکثر درخواست کد برای یک شماره در هر بازه
export OTP_RESEND_WINDOW_SECONDS=3600 # طول بازهٔ محدودیت درخواست
```

کد OTP شش‌رقمی با `random_int` ساخته می‌شود و فقط hash آن در `otp_codes` ذخیره می‌شود. برای هر شماره فقط آخرین کد معتبر است؛ درخواست جدید کد قبلی را جایگزین می‌کند. ارسال با `POST https://api.sms.ir/v1/send/verify`، هدر `x-api-key` و بدنهٔ `mobile`، `templateId` و `parameters` انجام می‌شود و فقط پاسخ HTTP 200 با `status: 1` موفق است. برنامه فایل `.env` را خودکار بارگذاری نمی‌کند؛ این مقادیر را در متغیرهای محیطی سرور PHP تنظیم کنید.

طرح جداول در `database/schema.sqlite.sql` و `database/schema.mysql.sql` قرار دارد و در اولین اجرا خودکار ساخته می‌شود. برای اتصال به جدول موجود `database_Saas`، ساختار جدول‌ها را با اسکیمای MySQL تطبیق دهید یا با `DB_DSN` به همان پایگاه‌داده وصل شوید.

## ساختار

```
public/          ریشه وب — index.php تنها نقطه ورود و فایل‌های ایستا
config/          تنظیمات مبتنی بر متغیرهای محیطی
database/        اتصال PDO و schemaهای SQLite/MySQL
src/app.php      احراز هویت، منطق برنامه و مدیریت درخواست‌های POST
src/router.php   مسیرها و صفحات
src/data.php     کاتالوگ پلن‌ها، جدول مقایسه، مقاله‌ها و پروژه‌ها
storage/         پایگاه‌داده SQLite (خارج از دسترس وب)

site/            خروجی استاتیک برای GitHub Pages (تولیدشده — دستی ویرایش نکنید)
tools/gen.py     تولیدکننده سایت استاتیک
tools/catalog.py کاتالوگ پایتونی، هم‌تراز با src/data.php
tools/demo.js    لایه داده سمت مرورگر برای نسخه استاتیک
```

کاتالوگ دو نسخه دارد (PHP و Python) و `tools/check_catalog.py` تفاوت‌ها را پیش از هر بیلد گزارش می‌دهد تا محتوا بی‌سروصدا ناهمگام نشود.

## نکات امنیتی

- فرم‌ها با توکن CSRF محافظت می‌شوند و خروجی‌ها با `htmlspecialchars` پاک‌سازی می‌شوند.
- کوئری‌ها فقط به‌صورت prepared statement اجرا می‌شوند.
- هدرهای امنیتی و CSP روی همه پاسخ‌ها اعمال می‌شود؛ فونت و دارایی‌ها میزبانی محلی دارند.
- کد یک‌بارمصرف با هش ذخیره می‌شود و به‌طور پیش‌فرض ۵ دقیقه اعتبار دارد. پس از ۵ تلاش ناموفق غیرفعال می‌شود و حتی کد درست هم پذیرفته نمی‌شود؛ کاربر باید کد جدید بگیرد.
- درخواست کد (ثبت‌نام و «ارسال دوباره») برای هر شماره در جدول `otp_requests` روی سرور شمرده می‌شود: حداقل ۹۰ ثانیه فاصله و حداکثر ۵ درخواست در ساعت. پاک‌کردن کوکی یا نشست این محدودیت را دور نمی‌زند.

## وضعیت قابلیت‌ها

پیاده‌سازی‌شده: صفحات عمومی، مقاله‌ها، پروژه‌ها، انجمن، پلن‌ها، فرم تماس، ثبت‌نام و ورود با پیامک، و سه پنل جدا با دسترسی نقش‌محور.

نیازمند تنظیمات یا اتصال بیرونی: ارسال واقعی پیامک (`SMSIR_API_KEY` و `SMSIR_TEMPLATE_ID`)، سرویس اجرای ایزوله Python و تنظیمات تولیدی زرین‌پال. اشتراک‌ها بازگشته‌اند؛ پرداخت نمایشی اشتراک فعال نمی‌کند. اجرای میزکار سروری تا راه‌اندازی و آزمون Runner قابلیت عملیاتی تأییدشده نیست.

## پرداخت تولیدی زرین‌پال

در محیط امن سرور PHP، `ZARINPAL_MERCHANT_ID` و `PAYMENT_BASE_URL` (مبدأ HTTPS دامنهٔ واقعی، بدون مسیر یا query) را تنظیم کنید؛ مقادیر محرمانه را در Git، HTML یا چت قرار ندهید. برنامه `.env` را خودکار نمی‌خواند. تا تنظیم درگاه، خرید غیرفعال است. GitHub Pages قادر به اجرای پرداخت PHP نیست؛ صرف انتشار نسخهٔ ایستا اتصال بانکی ایجاد نمی‌کند.

- خرید از `dashboard/subscription` با POST احرازشده و CSRF انجام می‌شود؛ مبلغ فقط از کاتالوگ سرور، با `currency=IRR` و تبدیل تومان × ۱۰ تعیین می‌شود.
- نشانی بازگشت ثبت‌شده در زرین‌پال: مبدأ تنظیم‌شده به‌اضافهٔ `/payment/zarinpal/callback`؛ نه Host ورودی کاربر.
- سفارش و Authority قبل از انتقال ذخیره می‌شوند. پارامتر Status هیچ اشتراکی فعال نمی‌کند؛ تأیید از API زرین‌پال با مبلغ ذخیره‌شده الزامی است. کدهای ۱۰۰/۱۰۱ همراه شمارهٔ پیگیری معتبر پذیرفته می‌شوند.
- فعال‌سازی و ثبت رسید در یک تراکنش با قفل کاربر انجام می‌شود؛ callback تکراری یا هم‌زمان فقط یک اشتراک ایجاد می‌کند. تمدید همان پلن ۳۰ روز به مانده اضافه می‌کند؛ تغییر پلن از زمان خرید است و ماندهٔ پلن قبلی منتقل نمی‌شود.
- تاریخچهٔ شخصی و بررسی مجدد: `dashboard/payment-history`؛ تاریخچهٔ مدیریتی همچنان نیازمند نقش مدیر است. اشتراک دستی/قدیمی رسید تراکنش بانکی نیست.
- خطای ارتباط موفقیت فرض نمی‌شود؛ سفارشِ دارای Authority از تاریخچه قابل بررسی مجدد است. خطای درخواستِ بدون Authority پیش از انتقال رخ داده و خرید جدید لازم دارد. سفارش requesting باقی‌مانده پس از قطع پردازش نیز پرداخت تأییدشده نیست.
- جدول `payment_orders` در هر دو اسکیمای SQLite/MySQL افزایشی است و داده‌های قبلی را حذف نمی‌کند. پیش از استقرار از DB پشتیبان بگیرید و ایجاد جدول را در staging بررسی کنید.
- آزمون‌های PHP با پاسخ کنترل‌شدهٔ درگاه، مبلغ، تأیید، بازپخش، هم‌زمانی و rollback را بررسی می‌کنند؛ تست HTTP واقعی برنامه نیز مالکیت، CSRF و غیرفعال‌بودن Nova را می‌سنجد. پرداخت بانکی زنده، MySQL و بررسی بصری مرورگر **آزموده نشده‌اند**. پیش از بهره‌برداری عمومی، تنظیم مرچنت/دامنه و یک تراکنش مجاز واقعی لازم است.

منابع رسمی: [اتصال به درگاه زرین‌پال](https://www.zarinpal.com/docs/paymentGateway/connectToGateway.html) و [واحد پول](https://www.zarinpal.com/docs/paymentGateway/moreFeatures/currency.html).

Nova AI فعلاً با پیام «به‌زودی» غیرفعال است و پیام‌ها و مصرف قبلی حذف نشده‌اند. در انجمن، هر کاربر برای هر پست فقط یک ذخیره دارد و «ذخیره‌های من» مجموعهٔ خصوصی او را نمایش می‌دهد؛ ذخیره‌های نسخهٔ ایستا فقط در همان مرورگر می‌مانند.
